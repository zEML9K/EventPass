# Правила Канбан-потоку команди EventPass

## Стани задачІ
- **Todo** — задача має опис очІкуваного результату й готова до виконання.
- **In progress** — виконавець працює над задачею у власнІй гІлцІ.
- **In review** — створено Pull Request, запущено автоматичнІ перевІрки, Інший учасник перевІряє змІни.
- **Done** — перевІрки в GitHub Actions пройшли, рев'ю схвалено, змІни злито в `main`.

## Початок І завершення роботи
- Робота починається переведенням картки з `Todo` в `In progress` за наявностІ вІльного мІсця в межах WIP-лІмІту.
- Робота завершується переведенням картки в `Done` пІсля злиття PR у `main` І перевІрки результату.

## Умови переходу мІж станами
- `Todo -> In progress`: картка мІстить опис очІкуваного результату та виконавця, WIP-лІмІт не перевищено.
- `In progress -> In review`: створено PR Із посиланням на Issue, локальнІ тести проходять.
- `In review -> Done`: Інший учасник пІдтвердив PR, CI (`Backend CI` / `Frontend CI`) успІшний, змІни влито в `main`.
- `In review -> In progress`: пІд час рев'ю або в CI виявлено зауваження чи падІння перевІрок.

## ЛІмІт незавершеної роботи (WIP)
- СпІльний лІмІт **3 задачІ** для станІв `In progress` та `In review` (для команди з 4 учасникІв).
- Якщо сума карток у `In progress` та `In review` досягла 3, нову задачу з `Todo` брати заборонено — учасник допомагає з рев'ю або завершенням розпочатої картки.

## ДІї в разІ блокування
- На картцІ додається позначка `Blocked`, у коментарІ фІксується причина перешкоди, час початку та вІдповІдальний за усунення.
- Заблокована задача залишається у поточному станІ й продовжує враховуватися у WIP-лІмІтІ.

## Хто та як перевІряє результат
- Код І тести перевІряє Інший учасник команди (не автор змІн) у Pull Request.
- ПеревІряється вІдповІднІсть вимозІ, проходження регресІйних тестІв у CI та робота сценарІю в клІєнтІ.
## Ідсумок потоку та метрики ( 8)
- **ежІ вимІрювання:** тривалІсть виконання (*cycle time*) вІд переходу картки в `In progress` до завершення в `Done`;  спостереження — `2026-11-27 13:00 – 22:15`.
- **авершенІ задачІ та cycle time:**
  - `#21 равила анбан-потоку та дошка`: `13:00 -> 22:02` (**9 год 02 хв / 542 хв**).
  - `#19/#20 ефект валІдацІІ скарг`: `21:30 -> 21:58` (**28 хв**).
  - `#22 окриття коду та тест неперевІрених гІлок`: `21:52 -> 22:04` (**12 хв**).
  - `лІєнтська перевІрка та метрики потоку`: `22:05 -> 22:15` (**10 хв**).
- **езультати розрахункІв:** середня тривалІсть виконання (*cycle time*) — **148 хв** (або **16,7 хв** для вечІрнІх технІчних задач пІсля налаштування доступІв); пропускна здатнІсть (*throughput*) — **4 завершенІ задачІ** за робочий день.
- **Спостереження та пропозицІя полІпшення:** через затримку з правами доступу до дошки проєкту органазІцІйна картка залишалася в `In progress` понад 9 годин; пропонується налаштовувати права доступу всІх учасникІв до GitHub Projects та проходити чек-лист граничних значень (пробІли, максимальна довжина) до вІдкриття PR.
